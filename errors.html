WinSCP errors: fixes for connection, host key and transfer problems

Most WinSCP errors fall into a few groups: the server refuses the login, the host key is unknown, a shell startup script breaks SFTP, or an automated job behaves differently from the graphical client. This page lists the common messages from the vendor's FAQ and what usually fixes them.

Before you chase a specific error

Many WinSCP errors disappear after a quick check of the basics. The vendor's FAQ has an entry for a pattern that comes up often: the program works on one machine, network or user account and fails on another. That almost always points to a difference in environment, such as a firewall, a proxy, a missing stored host key or settings saved under a different Windows user.

Run through this list first, and turn on session logging (the feature index lists logging, including XML logs) so you can see the exact step that fails.

  • Host name or IP address typed correctly
  • Protocol matches the server: SFTP and FTP are different services
  • Port matches: 22 for SFTP and SCP, 21 for FTP, unless your host says otherwise
  • User name and password or key come from the server's administrator
  • You are on the current release; updates arrive every one to three months

Cannot connect or log in

If the connection times out, the server is not reachable on that port from your network. Check the host, the port and any firewall or VPN between you and the server. If the connection is refused, nothing is listening on that port; a common cause is choosing FTP for a server that only runs SFTP, or the other way round.

If the login is rejected, the problem is the account. The vendor cannot reset passwords; only the server's administrator can. When other clients connect and this one does not, compare the protocol, port, encryption and authentication settings side by side. The FAQ has an entry for exactly this case. The connection guide shows where each setting sits in the Login dialog.

Host key warnings

The first time you connect to an SSH server, the program shows the server's host key fingerprint and asks whether to trust it. This is normal. Compare the fingerprint with the one your administrator or hosting provider publishes, then accept it so it is stored.

If the warning says the key has changed for a server you have used before, stop and ask. A reinstalled or migrated server gets a new key, and that is harmless. A change you cannot explain may mean someone is intercepting the connection.

Received too large SFTP packet

This message appears during login when something on the server prints text at the start of the session, usually an echo or a banner in a shell startup file such as .bashrc or .profile. The SFTP client reads that text as the start of a protocol packet and reports an impossible size.

The fix is on the server: make the startup script print only in interactive shells, or remove the output. The program itself has no setting for this, because the problem is in the data the server sends.

Transfer errors

  • Error code 4: a generic failure code that the SFTP server returns. The message that follows usually names the real cause, such as permission denied or a full disk.
  • Error 127 when copying: with SCP, the server's shell reports a command it cannot find. Switch the session to SFTP or ask the administrator to fix the server's shell environment.
  • Upload succeeds but setting permissions or the timestamp fails: you can write to the file but do not own it. Turn off preserving the timestamp and setting permissions in the transfer settings.
  • Files larger than 4 GB fail: the protocols handle large files, so check the local drive (FAT32 cannot hold them) and the server's limits.
  • Empty files or broken line breaks: check the transfer mode. Use binary for anything that is not plain text.
  • Changes do not show in the browser: the web server or the browser is serving a cached copy. Reload without the cache.

Scripts that fail outside the graphical client

A script that runs from your desktop but fails or hangs under Task Scheduler, SSIS or another service is the most common automation question in the vendor's FAQ. The service usually runs as a different Windows account. That account has no stored host key and none of the settings you saved in the graphical client, so the script waits for a confirmation that nobody can give.

Pass the host key in the open command with the `-hostkey` switch, and put every setting the script needs into the script itself. The Login dialog command Manage > Generate Session URL/Code produces a correct open line for you. To find out why a script failed, check its exit code and write a log file on every run.

When to update or switch

Many fixes arrive in regular releases, so install the current version from the download page before you spend long on an old bug. If the real problem is a service the program does not support, such as Google Drive, look at the alternatives instead. For a wider view of the program's strengths and limits, read the review.

FAQ

What does a connection timeout mean in WinSCP?

The program could not reach the server on the given port. Check the host name, the port and any firewall or VPN in between. Also check that the server really runs the protocol you chose.

What is error code 4?

It is a generic failure code that the SFTP server sends back. Read the message under it in the error box or the log; it usually says permission denied, file not found or no space left.

Why do I get 'Received too large SFTP packet'?

A shell startup script on the server prints text when the session starts, and that text breaks the SFTP protocol. Remove the output or limit it to interactive shells.

Why does my script work by hand but fail in Task Scheduler?

The scheduled task runs under another Windows account that has no stored host key or saved settings. Pass the host key with the -hostkey switch and keep every needed setting inside the script.

Can I undelete a file I removed on the server?

No. A file deleted on a remote server is gone unless the server keeps backups. To protect yourself in future, the preferences can move deleted remote files to a recycle bin folder on the server instead.

Can the vendor reset my server password?

No. The password belongs to an account on your server, so only its administrator or your hosting provider can reset it.
